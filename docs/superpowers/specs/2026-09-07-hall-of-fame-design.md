## 決定事項（オーナー確認済み）

| 論点 | 決定 |
|---|---|
| 傾向分析の窓 | **全期間 / 180日 / 60日** の3本立て（現行の28日1本を置き換え） |
| 殿堂入りの規模 | **30投稿分／アカウント** |
| 置き場所 | **`殿堂入り_<acc>` タブ＝DBとして永続化**（人が開いて分かる形） |
| 用途 | **PDCA（生成AIの入力）に使用。週次レポートには出さない** |
| 選定基準 | **表示回数の上位30本だけ**（全期間） |
| 対象 | 手動・AI問わず、公開して結果が出ている投稿 |
| お手本DBとの関係 | **別タブ**。殿堂入り＝自アカ実績の自動収穫／お手本DB＝競合・人が選んだ手本 |
| 手動行 | `保護` 列が非空の行は自動更新で消えない |

## 実装

### 1. 傾向分析の3窓（`analyzer.py`）

- `TREND_WINDOWS = (("60日", 60), ("180日", 180), ("全期間", None))`
- `analyze_windowed` の返り値に `out["trends"] = {窓名: {n_posts, by_time, by_weekday, by_length, by_tree}}`
- 既存キー `out["by_*"]` は **60日窓**（最も直近の傾向＝生成が読む主軸）。28日→60日でサンプルが増える
- `out["trend_top"] / ["trend_bottom"]` も60日窓（48時間未満の除外は維持）
- `analysis_to_rows` は3窓を `時間帯(60日)` のように窓名つきで出す（`インサイト分析_<acc>` タブ）

### 2. 殿堂入り（`hall_of_fame.py` 新規・純関数）

- `build_hall_of_fame(insight_rows, posts, existing, limit=30, now=...) -> list[dict]`
  - `保護` が非空の既存行を先頭に温存（人の手を消さない）
  - 残枠を **全期間の表示回数 上位** で埋める（保護行と `投稿後ID` が重複するものは除外）
  - 本文・フック型・内容型は `投稿_<acc>`（読み済み `posts_all`）から `投稿後ID` で結合＝追加読み取りなし
- `select_for_prompt(rows, now, k=3) -> list[dict]`
  - 30本から**日付ベースの決定的ローテーション**で3本。毎回同じ上位3本を見せると模倣が固定化し
    投稿が同質化するため回す（プロンプトに入れる具体例は3〜7本という設計原則にも従う）

### 3. シート（`sheets.py`）

- `HALL_OF_FAME_TAB_PREFIX = "殿堂入り_"` ／ `HALL_OF_FAME_FIELD_ALIASES`
  （順位/投稿後ID/投稿日時/本文/表示回数/エンゲージ率/フック型/内容型/保護/メモ/更新日）
- `Store.get_hall_of_fame(account)`（既定 `[]`）／`Store.write_hall_of_fame(account, rows)`

### 4. 生成（`generator.py`）

- `build_prompt(..., hall_of_fame=None)` に「## 殿堂入り（過去の当たり・実績順）」セクション
- `trend_top` と `投稿後ID` が重複するものは殿堂入り側から除外（同じ本文を2度見せない）

### 5. 配線（`main_weekly.py`）

- 生成日に `build_hall_of_fame` → `write_hall_of_fame` → `select_for_prompt` を `Generator.run` へ
- レポート（HTML／週次レポートタブ）には出さない

## やらないこと（YAGNI）

- 表示回数の期間正規化（アカウント成長でスケールが違う点は承知の上で生の表示回数を使う。
  「何が刺さったか」の実例としては有効で、正規化は解釈を複雑にする）
- 殿堂入りのER基準併用（オーナー判断で表示回数のみ）
